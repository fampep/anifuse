One API for every anime source.

A self-hosted Go service that bundles anime site resolvers behind a single POST /v1/resolve endpoint. Give it an AniList id and an episode; it asks the bundled sites and answers with the direct stream URL your player can open — HLS masters, MP4 files, sidecar captions, and the headers the CDNs expect.

Go 1.23 · zero dependencies Docker · one container AniKitty extension protocol Apache-2.0

What it does

Resolve, not host

AniFuse hosts no video. It resolves the URLs the sites already serve publicly and returns them to your player.

Failover built in

Ask without a provider and it tries every bundled site in order until one has the episode.

Sub and dub aware

Requests carry the language. Multi-audio masters serve both from one URL; dub-only rows are never played for a sub request.

Typed failures

404 means “not here”, 502 means “site unreachable or challenged” — clients can tell the difference.

Latest episodes

The newest episodes across every bundled provider, one feed. Fresh from GET /v1/latest.

Run your own

Docker — docker run -p 8080:8080 ghcr.io/fampep/anifuse:latest, or docker compose up --build from the repo.

From source — go run ./cmd/api (Go 1.23, no external modules).

Check — curl http://localhost:8080/healthz answers {"status":"ok",...}.

Install into AniKitty — in the app, add an extension with this host's base URL. AniFuse speaks the extension protocol, so it appears as a Source in the player.

# resolve Attack on Titan episode 1, sub
curl -sS -X POST http://localhost:8080/v1/resolve \
  -H 'content-type: application/json' \
  -d '{"anilistId":16498,"episode":1,"audio":"sub"}'
