AniFuse

One API for every anime source.

A self-hosted Go service that bundles anime site resolvers behind a single POST /v1/resolve endpoint. Give it an AniList id and an episode; it races the bundled sites and answers with the direct stream URL your player can open — HLS masters, MP4 files, sidecar captions, and the headers the CDNs expect.

What it does

Resolve, not host

AniFuse hosts no video. It resolves the URLs the sites already serve publicly and returns them to your player.

Failover is a race

Ask without a provider and every healthy site is tried in parallel — the fastest working stream wins.

Sub and dub aware

Requests carry the language. Multi-audio masters serve both from one URL; dub-only rows are never played for a sub request.

Typed failures

404 means “not here”, 502 means “site unreachable or challenged” — clients can tell the difference.

Run your own

Docker — docker run -p 8080:8080 ghcr.io/fampep/anifuse:latest, or docker compose up --build from the repo.

From source — go run ./cmd/api (Go 1.23, no external modules).

Check — curl http://localhost:8080/healthz answers {"status":"ok",...}.

Install into AniKitty — add an extension with this host's base URL and AniFuse appears as a Source in the player.

The API

Five endpoints, one protocol — the same JSON AniKitty speaks, so a running instance is a first-class source. Responses are gzip-compressed, CORS-open, and cached with ETags.

POST /v1/resolve

# resolve Attack on Titan episode 1, sub
curl -sS -X POST http://localhost:8080/v1/resolve \
  -H 'content-type: application/json' \
  -d '{"anilistId":16498,"episode":1,"audio":"sub"}'
FieldNotes
anilistIdrequired, > 0
episoderequired, > 0
audio"sub" (default) or "dub"
titleHintoptional search helper (needed by anizone)
provideroptional; pin one provider. Omitted = race all healthy providers.
// 200 — success
{
  "sources": [{
    "url": "https://cdn.example.com/ep1/master.m3u8",
    "headers": { "Referer": "https://embed.example.com/", "User-Agent": "Mozilla/5.0" },
    "label": "SUB",
    "subtitles": [
      { "url": "https://cdn.example.com/ep1/en.vtt", "label": "English", "language": "en", "mimeType": "text/vtt" }
    ]
  }],
  "provider": "anihosts",
  "tookMs": 812
}

// non-2xx — failure
{ "error": "AniHosts does not have this episode." }

provider names the winning site, tookMs the upstream resolve time, cached appears when a cached answer was replayed. Repeat answers come with X-AniFuse-Cache: HIT and Cache-Control.

GET /v1/latest

The aggregated newest-episodes feed. ?provider= pins one site, ?limit= caps the total (default 40, max 200), ?search= filters titles case-insensitively, ?sort=ep|name|mixed orders the rows. Cached for 3 minutes with an ETag for 304 revalidation.

# the newest episode named "frieren" across providers
curl -sS "http://localhost:8080/v1/latest?search=frieren&sort=ep"

GET /v1/providers

Lists the bundled providers with live health: id, name, siteUrl, status (ok | degraded | down), successRate, attempts and cooldownSeconds while a site is cooling off.

GET /healthz · GET /metrics

/healthz answers {"status","providers","uptimeSeconds","unhealthy"}. /metrics reports request counters and per-provider stats for dashboards.

About AniFuse

A small, fast resolve API in Go. Stdlib only, one static binary, one container.

Design

Registry pattern

A provider is a Resolve(ctx, Request); adding a site is one package plus one line.

Typed failures

missing → 404, blocked / unplayable → 502.

Bounded everything

Per-request timeouts, response caps, redirect caps, container-safe defaults.

Racing fan-out

Unpinned resolves race every healthy provider; the fastest stream wins.

Health memory

Blocked sites cool off for a minute instead of slowing every race.

Cache + singleflight

Identical requests share one upstream fetch; repeats replay from cache.

The same disclaimer applies: AniFuse hosts nothing and controls nothing on the sites it queries. You are responsible for the laws where you are and for the terms of every site it resolves. Use at your own risk.
